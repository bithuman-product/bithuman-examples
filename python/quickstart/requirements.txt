# local-avatar.py
# `[expression-2]`: without it an Expression 2 avatar is refused at open with
# "this avatar needs one more package" (measured 2026-09-23, bithuman 2.11.6);
# Essence 2 needs nothing extra.
bithuman[expression-2]>=2.11,<3
# local-avatar.py opens a window with cv2.imshow, which needs the GUI build.
#
# ★BOTH OpenCV distributions land here, and they collide. `bithuman` depends on
# `opencv-python-headless`; the line below asks for `opencv-python`. They own
# the same `cv2/` package — 39 of their 40 files are the same paths, including
# `cv2/cv2.abi3.so`, the extension that carries `imshow` — so whichever pip
# writes LAST is the cv2 you get. A requirements file cannot express install
# order (measured: swapping these two lines changes nothing), so it cannot pin
# the winner. Measured 2026-09-22 with pip 26.2.1, bithuman 2.11.6, opencv
# 5.0.0.93:
#
#   clean venv, pip install -r requirements.txt   ->  GUI: QT5    window works
#   opencv-python already there, then this file   ->  GUI: NONE   imshow gone
#   pip install opencv-python, then bithuman      ->  GUI: NONE   imshow gone
#
# So local-avatar.py does not rely on winning: require_window() checks before
# the model loads and names whichever thing is actually wrong. If you land on
# the headless build, this repairs it and touches nothing else:
#
#   pip install --force-reinstall --no-deps opencv-python
#
# Collapsing this to one distribution means changing what `bithuman` depends
# on, which is not this repo's to change.
#
# ★AND `bithuman` CANNOT SIMPLY DROP IT (measured 2026-09-23, both resolves):
# `bithuman` itself imports no cv2, but livekit-plugins-bithuman (1.8.2, and
# upstream main) does `import cv2` at module scope and declares no OpenCV — it
# gets one through `bithuman`. With the requirement removed, a clean
# `pip install bithuman livekit-plugins-bithuman` imports the plugin as
# `ModuleNotFoundError: No module named 'cv2'` on Linux and macOS alike. On
# macOS the collision is harmless anyway: the headless wheel reports
# `GUI: COCOA`. It bites on Linux, where headless is `GUI: NONE`.
opencv-python>=4.8

# cloud-avatar.py (LiveKit + OpenAI) — uses no cv2 at all
livekit-agents[openai,silero]>=1.4
livekit-plugins-bithuman>=1.4
